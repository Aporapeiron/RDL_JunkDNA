# RDL_JunkDNA

RDL の**未採用・未廃棄の思考断片**を保持するためのリポジトリ。

ここは完成した理論文書の保管庫ではなく、かといって単なる過去ログのアーカイブでもない。

> **今は使われていない、役割がまだ分からない、あるいは Core に入れるほど固まっていない。だが、後から別の関係と接続し、意味や機能を持つかもしれない断片を、生きたまま残す場所。**

名称の `JunkDNA` は、かつて「役割がよく分からない DNA」としてまとめられた領域の比喩から採っている。ここに置かれた断片も、現時点での機能不明・未採用を意味するだけで、無価値を意味しない。

---

## 位置づけ

```text
会話・観察・思いつき・疑問・反例候補
        ↓
RDL_JunkDNA
  ├─ まだ単独の断片
  ├─ 他の断片と接続し始める
  ├─ 検査・比較される
  └─ 必要なら再構成される
        ↓
RDL_Core / RDL_Functions / 各応用 Repo へ昇格
```

`RDL_Core` が現在採用している基底・仕様・必要最小限の Explanation を保持するのに対し、`RDL_JunkDNA` は**採用前の自由度を残す層**である。

したがって、

```text
Core にない ≠ 否定された
JunkDNA にある ≠ 採用された
古い ≠ 無価値
未整理 ≠ 間違い
```

とする。

---

## 何を置いてよいか

- 会話中に出た思考断片
- まだ名前のない構造
- RDL との接続が不明な観察
- 反例候補・破断候補
- 比喩や直感モデル
- 数式になる前の関係
- 既存概念との類似
- 後で検査したい違和感
- Core から外したが再利用可能性のある考え
- 一度不採用になったが、別の B では有効かもしれない断片

完成度は要求しない。

## 最小運用

基本的には `notes/` に Markdown を置くだけでよい。

```text
RDL_JunkDNA/
├── README.md
└── notes/
    ├── YYYY-MM-DD_短い題名.md
    └── ...
```

分類は必要になってから行う。最初から厳密なディレクトリ体系を作らない。

必要なら各文書の冒頭に、次のような軽い状態だけ付けてよい。

```text
status: raw | linked | tested | promoted | dormant
origin: chat | observation | experiment | imported
related: B, ξ, SILN, ...
```

ただし、これらの記入も必須ではない。

---

## 昇格

断片が十分に接続され、責務が明確になった場合のみ、適切なリポジトリへ再構成する。

```text
raw fragment
   ↓
connection
   ↓
inspection / comparison
   ↓
local stability
   ↓
promotion
```

昇格後も元断片を必ず削除する必要はない。成立経路そのものが後の再検査材料になりうる。

---

## RDL との関係

このリポジトリ自体も終端的な分類体系ではない。

「何を JunkDNA とするか」「いつ Core へ昇格させるか」という判断も有限な境界のもとで行われる。したがって、ここでの分類や運用ルールも必要に応じて変更してよい。

> **捨てるには早い。固めるにも早い。だから残す。**
